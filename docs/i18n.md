# 《千年虫》翻译规范（英语 en / 日语 ja）

## 1. 你要做什么
- 原文对照表：`src/i18n/zh/<章>.js`（由 `node tools/i18n-extract.js` 自动生成，不要改）。
- 译文写到：`src/i18n/<语言>/<章>.js`，格式完全相同：
  ```js
  Y2K.lang('en', {
    "file.c2_notes1231.text": "12.31\n\n21:50 Entered the lab. ...",
    ...
  });
  ```
- **每一个键都要翻译，键名一个字都不能改，不能多也不能少**（下面第 5 节的"追加键"除外）。值可以用 JSON 双引号字符串（换行写 `\n`），也可以用反引号模板字符串（注意不要出现 `${`）。整个文件必须是合法 JS。
- `props` 键的值是对象（属性窗口里的"标签: 内容"），键和值都要翻译。
- `seg|<中文名>` 是文件夹名/文件名的显示译名，值写译名即可（例：`"seg|我的文档": "My Documents"`，`"seg|对不起.doc": "Sorry.doc"`）。扩展名保持不变。
- 写完运行 `node tools/i18n-check.js <语言> <章>`，修到没有 ERROR。
- 先读 `docs/bible.md`（剧情、人物、真相）了解故事，再翻译。翻译的是一部悬疑游戏：线索、语气、伏笔都要保住。

## 2. 必须原样保留的东西
- `{player}`、推理板 `text` 里的 `{空格名}`（如 `{who}`）——一个都不能丢、不能改名。
- HTML / SVG 的标签、属性、class、style、id、坐标，只翻译标签之间给人看的文字。SVG 里的文字太长放不下时，可以缩短措辞或调小 `font-size`，但不要改结构。
- 数字、日期、时间、IP、机器名（JF-07、JYS-486）、BBS 账号 ID（sysop、wanfeng、qingman……）、鸽讯号、电话号码、呼机号、密码、五笔编码（SSJQ、sssg）、文件扩展名、网址。
- 一首诗如果是谜题材料（见第 4 节），中文原文必须保留。

## 4. 依赖中文的谜题：保留中文原件，加译注
本作的谜题有一部分建立在中文本身上。处理原则：**游戏世界里的"实物"保持中文原样（它们本来就是一台中国学校电脑里的东西），在旁边给出译文和译注，让不懂中文的玩家也能解；答案同时接受中文和外语写法。**
1. **"〔〕"原文标记**：凡是"打字方式"本身是线索的地方，在译文里该词后面紧跟用 〔〕 括起来的中文原字。包括：
   - 何蔓 / 青蔓 / 千年虫 / 伪造遗书里所有把"再"打成"在"的地方，以及遗书里的"以经"。例：`"See you〔在见〕."`、`"I won't let it happen〔在〕 again."`、日语 `「では〔在见〕。」`。**原文里每一处都要标，一处都不能漏**（这是全剧最重要的线索）；不要在没有错字的地方乱加。
   - 许嘉的五笔形近字错误（己经、末来、拔号等）同样标出：`"already〔己经〕"`。
   - 不要在译文里解释这是错字（第五章的资料会解释）。
2. **诗作为谜题材料时**（藏头诗《三月》、《夏至》、以及其他被谜题引用"第几行第几字/每行第几个字"的文字，比如贺卡）：保留中文原文，每行前加行号，下面给逐行译文。英文版在需要取字的谜题材料里，给每个可能被取到的字加拼音和意思，例如 `晚(wǎn, evening)`；日文版给读音即可。
3. **答案是中文字词的谜题**：译文里的 `prompt` 要告诉玩家可以用什么形式作答（中文原字、拼音、或译名），并用追加键（第 5 节）补上外语答案。例：
   - 《夏至》取字密码「晚风明天见」→ 英文追加 `"wanfengmingtianjian"`, `"evening breeze see you tomorrow"`, `"evening breeze, see you tomorrow"`；日文追加 `"晩風明天見"`, `"晩風、また明日"`, `"晩風明日会おう"` 等。
   - 人名答案（如"何蔓"）→ 英文追加 `"He Man"`, `"heman"`, `"Green Vine"`；日文追加 `"何蔓"` 的日文写法、`"青蔓"`。
   - 地点答案 → 追加译名的常见写法。
4. 中文网络用语（偶、酱紫、MM、886、7456）：译成该语言 2000 年前后的网络用语或意思相近的口语，可以在括号里保留原词增加时代感。
5. 计量、价格、地址照译；不要改任何时间线事实。

## 5. 追加键（只在需要时加）
- `"puzzle.<id>.answers+": ["...", "..."]` —— 文本题追加可接受的答案（引擎会和原答案合并，判定时忽略大小写、空格和标点）。
- `"puzzle.<id>.fields.<n>.answers+": [...]` —— 多栏题第 n 栏（从 0 开始）追加答案。
- `"puzzle.<id>.near+": { "错误答案": "接近时的反馈" }` —— 追加"差一点"的反馈。
- 选择题、多选题的 `options` 直接翻译即可，引擎按位置判定，不用改答案。
- 推理板的 `words` 直接翻译，引擎按词的 id 判定。

## 6. 风格
- 英语：自然、克制，像一部本地化认真的悬疑游戏。BBS 和聊天要有 1999—2000 年的网络感；人物口吻保持区分（许嘉简短技术化；何蔓礼貌、句末常有句号；周婷活泼爱用感叹号和 ~；宋知远书面自负；苏芮播音腔）。
- 日语：自然的现代日语。何蔓用です・ます体；学生之间用普通体；BBS 可以有当年的网络口语。日文中出现的中文地名人名用上表的日本汉字写法。
- 两种语言都不要漏掉任何伏笔，也不要多加原文没有的暗示。

## 7. 检查
`node tools/i18n-check.js en ch2` 会检查：键是否齐全、是否多出键、`{player}` 和推理板空格是否保留、HTML 标签数量是否一致、追加键格式是否正确、JS 是否合法。修到 0 个 ERROR。
